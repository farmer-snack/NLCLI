修复的 5 个问题
--------------
1) 插件包自带的 ClassIsland.Core.dll 会被当成真的核心库加载。
   插件作者常直接 dotnet publish 后整包打包，里面会带上 ClassIsland.Core / ClassIsland.Shared。
   原逻辑会按 deps.json 解析到插件目录的副本，于是插件里的 PluginBase、组件基类和宿主里的
   不是同一个类型：插件显示「已加载」，但注册的组件一个都不出现，也没有任何报错。
   → 加载时把 ClassIsland / ClassIsland.Desktop / ClassIsland.Core / ClassIsland.Shared /
     ClassIsland.Shared.IPC / ClassIsland.Platforms.Abstractions 一律绑定到宿主已加载的实例，
     忽略插件要求的版本号和插件包里的副本。

2) 插件包自带 Avalonia.dll 会造成同样的类型分裂。
   两份 Avalonia 同时存在时，插件创建的控件加入宿主视觉树会抛类型转换异常，或者干脆什么都不显示。
   → Avalonia* 前缀的程序集同样强制绑定宿主版本。

3) 插件包没有 deps.json（打包不规范，或者手工压缩）时，依赖全部解析失败。
   → 解析器返回空之后，按「插件目录下同名 dll」兜底加载；入口程序集也能这样找到。

4) 插件没打包某个依赖（多为框架类库），一加载就抛 FileNotFoundException。
   → 兜底复用宿主已经加载的同名程序集。

5) 插件带原生库（dll / so / dylib）但没有 deps.json，调用到原生依赖时直接闪退。
   → 在插件目录、runtimes/<平台>/native、runtimes/<平台>-<架构>/native 里按平台命名约定查找：
     Windows 补 .dll，Linux 试 lib*.so 与 *.so，macOS 试 lib*.dylib 与 *.dylib。

另外两处放宽 / 改进
------------------
6) API 版本校验原来只拦「低于 2.0.0.0」，现在：
   - 低于 2.0.0.0 的旧插件仍然拒绝（1.x 时代的 WPF 插件运行时 API 完全不兼容）；
   - 高于当前应用版本的不再阻止，只写一条提示，交给实际加载去检验；
   - 没写或写错 ApiVersion 的放行；
   - 顺手修了 "2.0" 这种省略段位的写法会被误判成低于 2.0.0.0 的问题（Version 默认段位是 -1）。

7) 插件加载失败时原来只吞掉一个异常对象，界面上看不出原因。现在：
   - 异常被包装成中文说明（「插件 X 加载失败：… 可能原因：…」），插件详情页直接可读；
   - 针对缺依赖、类型/方法缺失、架构不匹配（32 位插件跑在 64 位进程）分别给出对应提示；
   - 完整异常链同时打到控制台日志，方便反馈给插件作者。

可观测
------
插件详情页的状态徽章旁边，如果兼容层对这个插件做过调整，会多出一个「兼容层已介入」徽章，
悬停可以看到具体调整了哪些程序集（例如「ClassIsland.Core 2.0.0.0 已重定向到宿主版本 2.1.1.1」）。
正常情况下这个徽章不会出现。

验证方式
--------
搭了最小复现（两个版本的依赖库 + 引用旧版本的插件 dll + 两种加载策略）：
- 不做重定向：插件加载了自己那份旧依赖，与宿主那份 ReferenceEquals = False（两份不同类型）；
- 做重定向：插件直接用到宿主的高版本，插件调用返回的是宿主版本的结果。
说明「高版本宿主接住低版本引用」这条路是通的，这也是兼容层的核心假设。
